# Contributing to HRMD

Use the website's contribution form or the **Device addition, correction or
evidence** Issue template. Submissions should be reviewable at the field level.

- Identify the exact device, hardware revision, region and configuration.
- Give each proposed value, unit and scope. Preserve source ranges and inequalities.
- Provide the source URL and exact quotation, identifying its page, table or section.
- Attach an actual unhighlighted source capture; a transparent highlighted copy
  can help locate the evidence. Do not replace source text with a reconstruction.
- Record the actual visit/capture date where known. Do not assign today's date
  to an older capture.
- Explain the requested correction or addition. Partial records are welcome;
  do not invent missing values to make a device complete.

Matching official evidence is preferred. Other traceable sources can support
official omissions. PPD adoption uses official values or the project's current
algorithm; third-party PPD can be submitted as reference evidence. Source scope
and project defaults are distinguished. A source without a specified PPD location
defaults to central PPD; a source without a specified FOV axis defaults to
horizontal. Explicit contrary scope takes precedence.

Maintainers check model/configuration alignment and source support, then update
the adopted fields and their dependent calculations and exports. Submission is
not automatic acceptance.

Original code and curated-data contributions are accepted under the project's

include the source and any applicable attribution or license notice. See
[Third-party materials](THIRD_PARTY_NOTICES.md).
